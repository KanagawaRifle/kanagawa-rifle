# 2026-09-25: 解析・公開データ・表示・ルート構成の分離

状態: 採用

## 背景

機能単位の分割は導入済みですが、Markdown の解析と JSX 描画が `lib` に混在し、SNS 設定にも SVG が含まれていました。
大会の機能コンポーネントがページ全体と年度選択まで担当し、入会・推薦ページには料金表の同じ構造が繰り返されていました。

## 決定

- Markdown の構文木と目次は `lib/markdown`、React 描画は `components/Markdown` が担当する。
- 共通描画を `components` にまとめ、`config` には値を置く。設定・解析・機能データから UI への import を自動検査する。
- 大会のページ構成は `app/competitions/_components` に置き、ホームの告知には取得済みのデータを渡す。
- 入会・推薦の公開済み金額を各機能のデータに集約し、繰り返し部分を同じ表示部品で描画する。
- ニュースの読込窓口は維持し、記事解析と URL 生成を独立させる。

## 検討した方法

ページを小さなファイルへ移すだけでは責務の混在と重複が残ります。描画に必要なデータと処理の境界で分割します。
汎用的な CMS、リポジトリ基底クラス、独自キャッシュは、Git で更新する現在の運用に必要ないため導入しません。
会費の合計を自動計算する方法も、既存の案内だけでは適用条件や例外を確定できないため採用しません。

## 影響

公開 URL、ニュース API、キャッシュ期間、大会の公開年度と掲載内容を維持します。
会費表を HTML テーブルに変更し、読み上げ時の行・列の対応と狭い画面での操作を改善します。
Markdown の生の `pre` 要素に直接書かれた本文も保持し、パンくずの二重のナビゲーション要素を解消します。
既存のテストに加え、料金の対応、Markdown の表示、設計上の依存方向、ブラウザでの表示とアクセシビリティを検証します。
